# google-docs

**Status:** beta · **ToS risk:** none. Official API; reviewed and unit-tested with fakes, checked live only with an invalid credential (auth_error). See [plugin status](../README.md#plugin-status).

## Overview
A [graphrt](https://github.com/BimaPangestu28/graphrt) plugin for the [Google Docs API v1](https://developers.google.com/workspace/docs/api/reference/rest):
read documents (including tabs), create documents, insert text, replace text everywhere (fill templates) and
send raw batch updates. To find documents by name, copy, share or export them use [`google-drive`](../google-drive/).

Built with the [declarative REST layer](../docs/declarative-plugins.md): [`definition.mjs`](definition.mjs). Google
credentials use the same auth files as `google-sheets` (google-auth, google-token-endpoint and service-account, copied unchanged into [`lib/`](lib/)) through
[`lib/google-rest-auth.mjs`](lib/google-rest-auth.mjs); `insert_text` and `replace_all_text` build the
batchUpdate request from plain fields ([`lib/docs-requests.mjs`](lib/docs-requests.mjs)).

## Features
- **`get_document`:** structure and text; `include_tabs_content` returns every tab, `suggestions_view_mode`
  chooses how suggestions appear
- **`create_document`:** a new empty document with a title
- **`insert_text`:** at a UTF-16 `index` (1 = start of the body), or appended at the end
- **`replace_all_text`:** every occurrence with `replace_with`, optionally case-sensitive and limited to tabs;
  reports `occurrencesChanged`. Deleting the matches needs an explicit `delete_matches: true` (a missing or empty
  `replace_with` is refused, never treated as "delete")
- **`batch_update`:** any [batchUpdate requests](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/request)
  (styles, tables, images, deletions)
- **`api_request`:** any other endpoint (GET only for agents)

All writes accept `required_revision_id` (from `get_document`'s `revisionId`) so an edit fails instead of landing in
a document that changed meanwhile. Full reference: [OPERATIONS.md](OPERATIONS.md).

## Prerequisites
- Node.js >= 20, graphrt with plugin support
- A Google Cloud project with the Google Docs API enabled

## Installation
```bash
graphrt plugin install ./google-docs
```

## Configuration
| Env var | Purpose |
|---|---|
| `GOOGLE_REFRESH_TOKEN`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | OAuth refresh trio |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Path to a service account key file (scope `documents`); share each document with the service account's email |
| `GOOGLE_ACCESS_TOKEN` | A ready access token (used only when neither of the above is set) |
| `GOOGLE_DOCS_TOOL_ALLOW_BATCH_UPDATE` | `1` lets agent tools call `batch_update` and delete text with `replace_all_text` `delete_matches` |

Credential order: a node's `access_token` (needs `--trust-plugin google-docs`), then the refresh trio, then the
service account, then `GOOGLE_ACCESS_TOKEN`.

`GOOGLE_ACCESS_TOKEN` is ignored whenever the refresh trio or a service account key is configured (the
plugin cannot refresh after a 401, so it prefers a grant over a token of unknown age). An access token obtained
from a grant is cached in memory until a minute before it expires: after the grant is revoked or replaced in the
environment, calls keep using the cached token (failing with `auth_error` if Google rejects it) until it expires
or the plugin process restarts.

### Getting the credentials
1. Google Cloud console: enable the **Google Docs API**.
2. Either create an OAuth client and get a refresh token for `https://www.googleapis.com/auth/documents`
   (or `documents.readonly` for reads only), or create a service account, download a JSON key and share the
   documents with its `client_email`. A service account creating documents puts them in its own Drive.

**Pricing / limits:** free. Default quotas are 3,000 read and 600 write requests a minute per project, and 300 read
and 60 write requests a minute per user.

## Quick Start
```bash
GOOGLE_REFRESH_TOKEN=... GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... graphrt run google-docs/example.yaml --plugins .
```

## Usage
```yaml
# Fill a template copy (copy it first with google-drive.copy_file)
- id: fill
  type: google-docs.replace_all_text
  document_id: "{{#copy.data.id#}}"
  find: "{{customer_name}}"
  replace_with: "{{#start.customer#}}"
- id: note
  type: google-docs.insert_text
  document_id: "{{#copy.data.id#}}"
  text: "\nGenerated by graphrt."
```

## Agent policy
- `get_document`, `create_document`, `insert_text` and `replace_all_text` are tools (edits stay in version history).
- `replace_all_text` with `delete_matches: true` is a tool only with `GOOGLE_DOCS_TOOL_ALLOW_BATCH_UPDATE=1`.
- `batch_update` is a tool only with `GOOGLE_DOCS_TOOL_ALLOW_BATCH_UPDATE=1`, because raw requests can delete
  ranges, tables and images.

## Errors
Docs errors are `{"error": {"code", "message", "status"}}`, mapped by `status`: `UNAUTHENTICATED` → `auth_error`,
`PERMISSION_DENIED` → `permission_denied` (also when the API is disabled in the project), `NOT_FOUND` →
`not_found`, `INVALID_ARGUMENT`/`FAILED_PRECONDITION` (e.g. an index past the end, or a changed revision) →
`invalid_input`, `RESOURCE_EXHAUSTED`/429 → `rate_limited`. Writes are never retried after an unknown outcome
(repeating an insert would duplicate text): check the document first.

## Changelog
### 0.1.0 (unreleased)
- **Breaking:** `create_document` parameter `title` is now `document_title` (still sent to the Docs API as `title`). graphrt takes `title` from every workflow node, so the old name could never be set from a node (the required field made the node fail to load); tool calls that passed `title` must use `document_title`.
